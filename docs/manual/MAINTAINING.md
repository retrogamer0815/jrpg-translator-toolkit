# Maintaining the user manual

This page is for documentation contributors. For help using the application, start with the [user manual](README.md).

## Source and structure

The Markdown chapters in this folder are the primary documentation source. If producing a PDF or bundled manual, generate it from the same chapters so the editions stay consistent.

Keep the manual landing page focused on readers: a short introduction, task-based starting points, and the complete table of contents. Put technical explanations in the relevant chapters and contributor notes here.

## Release checks

- Check the manual's version note against the release it describes.
- Verify walkthroughs, UI labels, default shortcuts, and Profile scope against that release.
- Check chapter navigation, relative links, image references, and any anchors affected by heading changes.
- Link to official provider documentation for current AI availability and pricing rather than duplicating details that quickly become outdated.

## Screenshots

Use the [screenshot checklist](SCREENSHOTS.md) to track figures, filenames, coverage, and privacy checks. Review screenshots alongside the walkthroughs when the interface changes.

Keep screenshot-production status and checklist links out of the user-facing landing page. Never publish API keys or other sensitive information in screenshots.
